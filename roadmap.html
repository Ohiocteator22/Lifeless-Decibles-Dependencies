Development / Roadmap
Planning phase

Building Decibles, one phase at a time.

Decibles is being designed as a unified environment for application development. This roadmap outlines the intended path from technical research and architectural decisions to a potential initial release.

01 / Planned milestones

The development path

These phases describe the proposed development sequence. They are not delivery commitments, and their scope may change as technical feasibility is evaluated.

PHASE 00 Current focus

Product definition and planning

Establish what Decibles is, which problems it should solve, and what belongs in its initial scope.

  • Define the product direction and target audience.
  • Identify the initial application categories.
  • Establish the modular architecture philosophy.
  • Define the project manifest and import strategy.
  • Identify initial technology candidates and non-goals.
Objective: Establish a coherent specification before implementation.
PHASE 01 Proposed

Technical feasibility

Investigate the riskiest assumptions before committing to implementation details or an extensive technology stack.

  • Evaluate PySide6/Qt for the desktop interface.
  • Assess editor components and language-server integration.
  • Investigate debugging and terminal integration.
  • Evaluate Python desktop packaging and backend workflows.
  • Review dependency distribution, security, licensing, and maintenance.
Exit goal: Identify a technically credible initial implementation scope and resolve or explicitly accept major risks.
PHASE 02 Proposed

Architecture and detailed design

Turn the approved direction into explicit module boundaries, interfaces, data models, and implementation specifications.

  • Define core services and module contracts.
  • Specify project discovery, creation, and import behavior.
  • Design dependency metadata and environment management.
  • Define diagnostics, task execution, and logging conventions.
  • Establish test strategy and security boundaries.
Exit goal: Produce an implementation-ready architecture with clear responsibilities and acceptance criteria.
PHASE 03 Proposed

Core foundation

Build the minimum desktop application foundation needed to support reliable project workflows.

  • Establish the application shell and navigation.
  • Implement settings, logging, and error reporting.
  • Introduce the project model and manifest validation.
  • Implement task execution without blocking the UI.
  • Establish automated testing and packaging for Decibles itself.
Exit goal: A stable foundation that can host development integrations.
PHASE 04 Proposed

Initial development workflows

Integrate a deliberately limited set of technologies and deliver useful end-to-end workflows instead of superficial language support.

  • Create and import supported projects.
  • Configure project-scoped environments and dependencies.
  • Provide editing, diagnostics, and execution.
  • Integrate debugging where technically feasible.
  • Implement appropriate build and packaging workflows.
Exit goal: Complete, testable workflows for the selected initial technologies.
PHASE 05 Proposed

Validation and release preparation

Verify that the supported workflows behave reliably on real systems and that the application can be distributed safely.

  • Test project creation, import, and recovery scenarios.
  • Validate dependency integrity and installation failures.
  • Test packaging, clean installations, and upgrades.
  • Document supported environments and known limitations.
  • Prepare release artifacts and user documentation.
Exit goal: Determine whether the initial release meets defined quality and reliability criteria.
PHASE 06+ Long-term

Expansion and refinement

Expand based on actual user needs, verified feasibility, and the maintainability of the initial system.

  • Consider additional languages and framework integrations.
  • Improve project templates and developer workflows.
  • Evaluate Linux and macOS support.
  • Refine accessibility, performance, and usability.
  • Consider additional packaging and distribution capabilities.
Exit goal: Expand deliberately without compromising reliability or turning the IDE into an unmaintainable collection of integrations.
02 / Development principles

What guides the roadmap

The roadmap is organized around a few principles intended to keep the project useful, maintainable, and realistic.

PRINCIPLE / 01

Complete workflows over checklists

A small number of well-integrated technologies is more useful than a long list of languages that only have syntax highlighting.

PRINCIPLE / 02

Use established tools

Decibles should orchestrate proven compilers, SDKs, debuggers, and package managers instead of unnecessarily recreating them.

PRINCIPLE / 03

Keep the core lightweight

Optional integrations and development tools should be installed when needed rather than bundled indiscriminately.

PRINCIPLE / 04

Verify before expanding

Major technical assumptions should be investigated before they become expensive architectural commitments.

PRINCIPLE / 05

Preserve existing projects

Conventional source files and ecosystem configuration should remain usable without unnecessary proprietary conversion.

PRINCIPLE / 06

Make limitations visible

Compatibility claims, integration levels, and known limitations should be documented honestly and tested on the actual target platform.

03 / Scope control

What the initial release is not trying to do

A realistic initial release needs clear boundaries. These are current planning constraints, not permanent restrictions on the project.

Not every language at launch

Language support will expand according to the quality and completeness of each integration.

Not every SDK bundled

Large toolchains and optional dependencies should remain independently managed wherever practical.

Not a game engine

Decibles is intended for application development, not as a general-purpose game engine or game-development environment.

Not simulated compatibility

Static checks or simulations must not be represented as genuine native execution or builds on another operating system.

04 / Transparency

A roadmap, not a release promise.

Decibles remains in the planning phase. No public release date has been established, and no implementation milestones should be considered complete until they have been built and verified. This roadmap will evolve as feasibility research, architecture decisions, and implementation provide better evidence about the project's scope and timeline.
